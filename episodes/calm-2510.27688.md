## Introduction

Large language models are powerful, but they're held back by the way they generate text—one token at a time. This process is slow and limits how efficiently they can operate. A new approach called Continuous Autoregressive Language Models, or CALM, challenges this by shifting from predicting the next token to predicting the next continuous vector. Instead of handling text as a sequence of discrete tokens, CALM compresses a group of tokens into a single continuous vector, allowing the model to generate language in larger chunks. This reduces the number of steps needed to produce the same output, making the process more efficient. The research introduces a new framework for training and evaluating these continuous models, showing that CALM can match the performance of traditional models while using far less computation. This opens up a new path toward more efficient language models.

## Contributions

Large language models generate text one token at a time. This is slow and uses a lot of computation. Tokens are like words or parts of words, and each one carries only a little information. To make models more efficient, researchers have tried using bigger chunks of text, like phrases, but this runs into a problem: the number of possible phrases grows too fast to handle. The way models predict the next token is also limited because they need a huge list of possible choices. This means the models can't scale efficiently, even though they're getting more powerful.

The way language models generate text is too slow and inefficient. Models generate one token at a time, which is slow and limits their ability to handle long texts or large contexts. The CALM approach generates text in larger chunks by predicting continuous vectors instead of individual tokens. This reduces the number of steps needed to produce the same output, making the process more efficient.

Traditional methods for language modeling rely on discrete tokens, which limit information density. Discrete tokens carry only a small amount of information, and increasing this capacity would require an exponentially larger vocabulary, which is impractical. CALM uses continuous vectors to represent multiple tokens at once. This allows the information density to scale by simply increasing the size of the vector, without the need for an exponentially larger vocabulary.

Evaluating language models without explicit probability distributions is difficult. Traditional metrics like perplexity depend on knowing the probability of each token, which isn't possible in the continuous vector space. The authors introduce BrierLM, a new evaluation metric based on the Brier score. This metric works without needing explicit probabilities and can be calculated by sampling from the model, making it ideal for CALM.

Controlling the generation process in continuous models is challenging. Temperature sampling in traditional models adjusts the randomness of predictions by manipulating probabilities, but this isn't possible in the continuous vector space. The authors develop a new sampling algorithm that works without probabilities. It allows for controlled generation by adjusting the diversity of outputs, and it's efficient enough to use in practice.

## The autoencoder

Here is how it works. The method has four pieces: the autoencoder, the generative head, BrierLM evaluation and temperature sampling.

The autoencoder takes a group of K tokens and turns them into a single continuous vector. It starts by mapping each token to an embedding using a position-wise feed-forward network. These K embeddings are then flattened and compressed into a d-dimensional representation with a linear layer. This is passed through another feed-forward network and a linear projection to get the l-dimensional latent vector z.

Next, the decoder transforms z using a linear layer and another feed-forward network to get a d-dimensional hidden state. This is expanded to Kd dimensions and reshaped into K hidden states. Each of these is passed through a feed-forward network and projected to vocabulary logits using the same embedding matrix used for input. The tokens are reconstructed by taking the argmax of these logits.

The autoencoder is trained using cross-entropy loss over all K tokens. To make the latent vector more robust, it uses variational regularization. Instead of outputting a single vector, the encoder outputs the mean and standard deviation of a Gaussian distribution. The latent vector is sampled from this distribution, and a KL divergence loss is added to the total loss. This encourages the latent space to be smooth and structured.

To prevent some dimensions from collapsing, the KL divergence loss is clipped at a minimum value. Dropout is also used during training: the latent vector is randomly dropped, and some input tokens are masked. This makes the autoencoder more robust and context-aware. The final latent vector has l = one hundred and twenty-eight dimensions, allowing it to encode information redundantly while keeping high reconstruction accuracy.

## The generative head

The generative head takes the Transformer's hidden state and a random noise vector as inputs. The hidden state comes from the previous step, and the noise vector is sampled from a uniform distribution. Each dimension of the noise vector is chosen randomly between negative half and positive half. Both the hidden state and the noise vector are projected into the same dimension as the Transformer's hidden state using separate linear layers. This gives the model a way to generate a continuous vector while keeping randomness in the process.

The noise vector is then refined through a series of residual MLP blocks. Each block fuses the current noise representation with the hidden state using two linear layers. After that, a SwiGLU activation is applied, which uses an intermediate dimension equal to the Transformer's hidden dimension. A residual connection adds the original input to the output of this block. This process is repeated for L blocks, where L is a quarter of the number of Transformer layers. These blocks help the model gradually improve the noise vector into a more accurate representation.

After processing through all the blocks, the refined noise is projected to the target dimension l using a final linear layer. This gives the output continuous vector, which has l = one hundred and twenty-eight dimensions. This vector is then used to generate the next chunk of K tokens through the autoencoder's decoder.

During training, the model compares the generated vectors with multiple target samples drawn from a conditional Gaussian posterior. The energy loss is calculated using pairwise distances between the generated samples and between generated and target samples. This ensures the model produces diverse yet accurate outputs. The number of model-generated samples is N = eight, and the number of target samples is M = one hundred. This setup helps reduce the variance in the loss while keeping training efficient.

## BrierLM evaluation

The BrierLM evaluation measures model quality without needing probabilities. It uses Brier scores for n-grams, from one to four tokens long. For each n-gram, it compares two generated samples. First, it checks if the n-gram matches either sample. Then, it checks if the two samples match each other. The Brier score combines these checks into a formula. The result for each n-gram is then multiplied together, and the fourth root of that product is taken. Finally, the score is scaled by one hundred to make it easier to interpret, ranging from zero to one hundred. This approach avoids needing explicit probabilities, which are hard to get from continuous models. Instead, it uses only samples from the model. The method works by treating each n-gram as a single outcome, similar to how BLEU scores work. The geometric mean ensures that all n-gram sizes contribute equally to the final score. This makes BrierLM a fair and reliable way to evaluate continuous language models like CALM.

## Temperature sampling

Temperature sampling adjusts how diverse the model's outputs are, without needing explicit probabilities. It takes generated samples and a temperature parameter, which controls randomness. The temperature is split into an integer part and a fractional part. For the integer part, the algorithm draws several samples and only accepts them if they're all the same. If not, it restarts. For the fractional part, it uses a special method to simulate a biased coin flip based on the probability of each sample. If both steps succeed, the sample is accepted. If not, the process restarts.

At low temperatures, drawing many identical samples becomes impractical. So, the algorithm draws a large batch of samples instead. It counts how often each sample appears and creates candidate sets based on how many times they repeat. If no sample repeats enough times, it lowers the repetition requirement until it finds valid candidates. The final sample is chosen based on how many combinations each candidate can form. This method works with any model that can generate samples, not just CALM. It lets users control output diversity efficiently, even when probabilities aren't available.
